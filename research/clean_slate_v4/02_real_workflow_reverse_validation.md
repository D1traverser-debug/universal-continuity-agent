# Clean-Slate v4 — 真实业务工作流反推审计

Status: `DESIGN_INPUT / REVERSE_VALIDATION / NO_PRODUCTION_REFACTOR`
Date: 2026-10-13

## 目的

用用户真实业务工作流反查 `01_normalized_functional_requirements.md`，不从架构倒推需求。检查四类问题：

1. 一级能力遗漏；
2. 同类能力被拆散；
3. 上下层错位；
4. 只在复杂真实场景中才暴露的必要行为。

本轮使用五类真实场景：财经写作、A 股荐股/复盘、AI 视频制作、长篇小说/大规模文本蒸馏、总控系统维护。

---

## 一、总体结论

v0.1 的方向正确，但不是稳定版本。真实场景反推后发现三处结构性缺陷和若干二级遗漏：

### 结构性缺陷 1：用户要求、任务意图、作用域被拆散

v0.1 把“理解目标”放在 A，把“用户要求落位”放在 D/G，把“继承”放在 E，把优先级放在 C。这会让同一个用户输入在多个一级能力之间来回切割。

真实场景已经证明，这不是小问题：
- “新写一篇文章”不能继承上一篇文章的业务状态；
- “继续某篇文章”必须恢复精确任务；
- “审视财经写作系统”不能被错误路由成继续某篇文章；
- “以后视频角色必须统一资产”是长期要求变更，不是当前镜头任务；
- 用户撤销旧要求时，旧要求必须失效，而不是继续和新要求并存。

因此需要独立一级能力：**用户意图、要求与作用域治理**。

### 结构性缺陷 2：任务编排只写“多 Agent”，没有覆盖真实执行资源

真实视频与写作工作流表明，系统调度对象不仅是 Agent，还包括：
- 工具；
- 模型；
- provider；
- connector；
- 脚本/Runtime；
- 外部素材；
- 额度、成本和执行窗口。

一个 Agent 声称“会做”也不等于当前会话真的具备可执行能力。因此 v0.1 的 C 必须扩展为 **执行编排与资源协调**，包含当前能力握手、工具/模型路由、资源与额度、产物依赖和工作流可达性。

### 结构性缺陷 3：任务状态、业务数据、知识和产物不应塞进同一个能力

v0.1 的 E 同时负责“跨会话 checkpoint”和“统一知识治理”。A 股、视频和小说场景证明这些对象生命周期完全不同：

- 任务 checkpoint：回答“做到哪一步”；
- A 股冻结快照：回答“当时决策基于哪一版市场数据”；
- 视频角色/场景资产：回答“跨镜头使用哪一个批准版本”；
- 小说语料/蒸馏结果：回答“读了哪些章节、覆盖率多少、哪些结论只适用于单书”；
- 可交付 Word/视频文件：回答“当前交付给用户的到底是哪一个真实产物”。

因此 v0.1 的 E 应拆成两个一级能力：
1. **持久任务状态与跨会话连续性**；
2. **数据、产物与知识治理**。

### 同时应合并一处重复

v0.1 的 D“理解系统结构并在正确位置变更”和 G“子系统与 Agent 生态治理”高度重叠。两者本质都是：

> 知道系统有什么、谁负责、在哪里、依赖谁、怎样安全变更、怎样升级/退役。

应合并成一个一级能力：**系统/子系统拓扑与变更治理**。

因此：v0.1 的 9 个一级能力不应机械保留。反推后更合理的是 **10 个一级能力**。

# 二、五类真实业务逐项反查

## 1. 财经写作

### 真实压力点
- 新文章、继续旧文章、全局审视写作系统是不同作用域，不能串任务。
- Research → Audit → Editorial → Title → Draft → Editorial Audit → Delivery → Final Audit 之类流程不能因为“知道规则”就算执行过。
- 双版本、Word 交付、最终文件必须确认是当前真实可交付物；仅有历史 hash 或状态记录不够。
- 自审可能漏检，需要与生成路径不同的结构/事实/交付验证。

### v0.1 覆盖
A、B、E、I 有部分覆盖。

### 暴露缺口
1. **意图/作用域治理不够明确**：NEW TASK / CONTINUE / SYSTEM AUDIT 不能混。
2. **当前执行能力真实性**不够明确：规则、能力声明、Agent 角色不能替代当前实际 capability。
3. **当前交付物身份与可见性**属于产物治理，不应只靠 checkpoint。
4. **生产与审核的证据独立性**需要成为质量验证的二级要求。

### 处理
- 新增一级 A：意图、要求与作用域治理；
- 扩充执行编排；
- 新增数据/产物/知识治理；
- 质量验证加入独立/异构验证与当前交付物验真。

---

## 2. A 股荐股 / 盘后复盘

### 真实压力点
- 推荐前存在盘前输入、冻结、市场状态、候选池、QA 等严格依赖。
- 盘后需要涨停池、跌停池、炸板池、强势股池、昨日涨停池等完整输入；关键输入缺失时不能假装完整。
- 数据来源可能出现不同口径，必须知道来源、时间、交易日、冻结版本并做 reconciliation。
- 盘前判断必须能和盘后真实结果连起来，形成复盘和学习，而不是每天重写一套故事。
- 当前行情/Level-2/公告等时效事实不能被旧缓存代替。

### v0.1 覆盖
B、C、E、F、H 有部分覆盖。

### 暴露缺口
1. **时间语义和冻结快照**没有明确归属。
2. **数据血缘**没有明确要求：最终荐股必须能追溯到使用了哪些冻结输入。
3. **关键数据不完整时的门禁**不够明确。
4. **来源冲突的 reconciliation**需要从“多源比较”提升为数据治理行为。
5. **复盘结果如何晋升为方法改进**需要严格区分单日证据和稳定规则。

### 处理
这些不需要新建“A 股专属总控”，应落入：
- 数据/产物/知识治理：时效、来源、快照、血缘、完整性、冲突；
- 执行编排：前置门禁和依赖；
- 自我进化：从真实结果到候选改进再到晋升。

---

## 3. AI 视频制作

### 真实压力点
- 角色、服装、场景、道具、风格、光影、动作必须跨镜头保持连续。
- 需要角色母版、关键帧、镜头状态、首尾状态等真实资产，而不是只靠提示词描述。
- 不同镜头可能应路由到不同视频模型/图像模型/真实素材/动效工具；质量优先但需要考虑成本、额度和重试预算。
- 多 Agent 必须各司其职并有真实产物依赖；不能出现上游没有产出 artifact、下游却声明依赖它的“静态死链”。
- 探索实验不能污染权威生产轨。
- “总控综合 QA”不能冒充多个真正独立执行过的 reviewer。

### v0.1 覆盖
C、E、G、I 有部分覆盖。

### 暴露缺口
1. **模型/工具/额度/成本/质量路由**不能只写 Agent 选择。
2. **工作流可达性**必须验证“每个必需输入都有真实 producer”。
3. **资产身份、版本和连续性**属于产物治理。
4. **探索轨与生产轨隔离**是通用运行约束。
5. **审核是否真的独立执行**需要证据，不是角色名称。

### 处理
- C 扩展为执行编排与资源协调；
- 新的数据/产物治理能力管理 asset identity/version/lineage；
- 加入生产/探索隔离约束；
- QA 增加真实 reviewer/evidence 约束。

---

## 4. 长篇小说 / 大规模文本蒸馏

### 真实压力点
- 用户要求“整本做完再停”，不能把一章、一卷或阶段总结误当完成。
- 阅读大部头时必须知道已读范围、coverage、章节/hash、next-location，跨窗口恢复不能重读或跳读。
- 单书提炼出的规律不能自动升级成通用小说法则，需要跨作品验证、反例和 anti-overfit。
- 蒸馏不是摘要；提炼出的结构、节奏、冲突等方法必须在原创中实际使用。
- 每本书的研究证据应有独立归属，跨作品综合另有层级。

### v0.1 覆盖
A、B、E、H 有较强覆盖，但细节不够。

### 暴露缺口
1. A 缺少明确的**完成单位与停止边界**。
2. 连续性能力缺少**进度游标/coverage**这种可恢复进度语义。
3. B/H 缺少**结论适用范围、反例与反过拟合**要求。
4. 单书证据、跨书方法论、正式通用知识需要不同晋升层级。

### 处理
均作为二级能力补入，不新增“小说专用顶层功能”。

---

## 5. 总控系统维护

### 真实压力点
- 发现重复故障时必须找共同失败类和正确抽象层，而不是继续加提示语、测试或补丁。
- 修改系统前要知道真实 authority、依赖和影响范围。
- 修复后不能只看 CI 绿灯；要知道关键 invariant 是否真的被机械阻止。
- direct-main 错误写路径已经证明：文字规则可以存在，但如果危险能力仍然可执行，控制并未真正关闭。
- 维护应能主动研究更好的机制，但新方案必须替代/删除旧机制，而不是继续堆层。

### v0.1 覆盖
D、F、G、H、I 覆盖较强。

### 暴露缺口
1. D 与 G 重复，应合并。
2. “关键 invariant 尽可能机械执行”应成为跨域约束，而不是某次事故的特殊规则。
3. 质量验证必须区分“文字规则存在 / 测试覆盖 / 工具层真正拒绝”不同证据等级。
4. 自进化需要明确“晋升”和“退役”是一条完整生命周期。

# 三、归一化后的一级能力建议

真实场景反推后，建议 v0.2 采用以下 10 个一级能力：

| ID | 一级能力 | 说明 |
|---|---|---|
| A | 用户意图、要求与作用域治理 | 识别用户在“做任务 / 改要求 / 继续任务 / 审视系统”等不同意图；管理要求优先级、冲突、替代和作用范围 |
| B | 目标驱动的自主任务完成 | 从明确完成单位出发，持续推进直到真正完成，除非确实需要用户介入 |
| C | 知识/证据获取、提炼与最适配决策 | 主动学习、比对、处理不确定性、大规模蒸馏，并把知识用于执行 |
| D | 执行编排与资源协调 | 任务图、并发、Agent、工具、模型、provider、能力、额度、成本、产物依赖和汇合 |
| E | 系统/子系统拓扑与变更治理 | 知道系统结构、责任、位置、依赖、生命周期；在正确位置安全增删改查 |
| F | 持久任务状态与跨会话连续性 | checkpoint、进度游标、精确继承、任务隔离、旧任务迁移与恢复 |
| G | 数据、产物与知识治理 | 来源、时间、版本、快照、hash、血缘、完整性、冲突、资产、交付物、知识晋升与退役 |
| H | 运行监测、故障诊断与可靠恢复 | 异常发现、阻断扩散、ambiguous outcome、重试/隔离/降级、恢复验证 |
| I | 自我进化、主动维护与复杂度控制 | 失败类学习、方案研究、候选验证、晋升/回滚/退役、空闲维护、复杂度预算 |
| J | 质量验证、完成证明与用户交付 | 按要求验收、独立证据、当前产物验真、能力级覆盖、真实完成状态、最终汇报 |

这个结构不是为了把 9 改成 10，而是做了三次归一化：
- 新增一个真实缺失：A；
- 拆开一个混杂能力：旧 E → F + G；
- 合并一个重复能力：旧 D + 旧 G → 新 E。

净结果正好是 10。

# 四、无需升格为一级能力的细节

本轮还发现很多重要要求，但它们有明确上层，不应再制造顶层模块：

- 视频角色一致性 → G 的资产身份/版本/血缘；
- A 股交易日/冻结时间 → G 的时效/快照；
- 小说整本做完再停 → B 的完成单位/停止边界；
- 小说 coverage/hash/next-location → F 的恢复游标 + G 的来源身份；
- 多 reviewer → J 的独立/异构验证；
- 模型额度与成本 → D 的资源调度 + 跨域成本约束；
- current-session capability handshake → D 的执行能力真实性；
- 工具超时未知结果 → H 的 ambiguous outcome；
- 探索轨/生产轨 → D/H 的执行隔离；
- 单书不能直接升级通用规律 → C/G/I 的适用范围与知识晋升；
- 新要求替代旧要求 → A 的要求生命周期；
- 新任务不得继承旧业务状态 → A/F 的作用域和任务隔离。

# 五、新增跨域约束

真实场景要求在 v0.1 基础上补三条通用约束：

## X11 关键约束应优先机械化
对高影响不变量，只写提示语或文档不等于控制。只要环境允许，应优先让权限、状态机、schema、transaction/CAS、runtime gate 或其他可执行机制阻止非法动作；若只能依赖约定，必须如实降低保证等级。

## X12 关键前置条件缺失时不得静默降级
当完成结论依赖的数据、能力、授权或证据缺失时，应阻断受影响结论或明确降级，不能悄悄换成更弱输入后仍宣称原目标已满足。

## X13 实验与权威生产状态分离
探索、试验、候选知识、候选方案可以并行存在，但不得在未验证/未晋升前污染当前权威生产状态。

# 六、下一阶段入口

真实工作流反查完成后，需求树不应立即进入框架选择。下一步是为 A–J 的关键二级能力定义可验收的行为标准，重点包括：

- 什么输入触发；
- 系统必须做什么；
- 哪些状态变化必须留下；
- 哪些异常必须 fail/hold/recover；
- 交付时怎样证明满足；
- 哪些场景可以作为回归/验收。

只有这些标准稳定后，才从需求 + 风险反推 clean-slate 架构。

## 当前边界

本文件是需求设计与反推审计，不授权生产架构重构。

material-main 的机械写入防护问题仍为 OPEN/BLOCKED；本次反查反而把“关键约束应优先机械化”提升为通用需求，不能把文档更新本身当作该事故已经关闭。
