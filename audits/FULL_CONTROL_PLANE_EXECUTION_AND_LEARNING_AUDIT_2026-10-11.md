## Root failure classes

### 1. Untrusted control input

A verifier can still overclaim if its **expectation, replay history, session observation, or other verification input is caller-authored and underconstrained**. Less specified input must never produce stronger assurance.

Accepted defense:
- exact expectations are mandatory for execution receipts;
- replay history needs an authority/completeness verifier when anti-replay is claimed;
- `ATTESTED_ISOLATED` cannot be promoted from self-asserted identity/proof strings;
- duplicate/conflicting observations fail closed.

### 2. Plan-execution disconnect

A machine-readable audit plan, mode name, fault list, or policy declaration does not prove the checks ran.

Observed defect: `runtime.system_audit` could compute `FULL_CONTROL_PLANE` / `SYNTHETIC_FAULT_INJECTION`, while CI passed no changed paths and the runtime merely printed the plan.

Accepted defense:
- CI derives actual changed paths and passes them into the planner;
- selected synthetic faults are executed, not merely listed;
- output has an explicit evidence ceiling separating local CI from remote owner sweep evidence.

### 3. Schema-coercion privilege escalation

Permissive coercion can transform malformed metadata into permission. Example class: string `"false"` becoming truthy in a boolean field.

Accepted defense: permission/recovery/side-channel booleans are type-checked and malformed values fail closed.

### 4. Complete-discovery / incomplete-presentation split

Discovery can be globally complete while the UI/helper silently truncates legal candidates, creating a new closed-world boundary after discovery.

Accepted defense:
- resolver no longer silently caps the authoritative candidate set to five;
- any intentionally truncated presentation is explicitly separate from the complete candidate set;
- incomplete discovery cannot auto-resume even when one partial candidate is visible;
- cross-owner task-id collisions fail closed instead of deduping silently.

### 5. Historical-proof version laundering

A real historical receipt may cease to satisfy a hardened current contract. Preserving evidence is correct; silently reclassifying it as current assurance is not.

Observed remotely: A-share had a real 2026-10-10 methodology self-audit produced before receipt contract 1.3 exact-action binding.

Accepted defense: retain it as historical maintenance evidence, but mark it inadmissible as current v1.3 action-level operational PASS.

### 6. Suite/history amnesia

A new audit/fault suite must not delete previously defended failure classes merely because the implementation is rewritten. A replacement suite that forgets old counterexamples is a regression in the verifier itself.

Accepted defense: historical synthetic fault classes were restored and new classes were appended rather than replacing the prior corpus.

## Second-order challenge

The accepted repair was attacked again after first green regression:

- **Evidence ceiling:** local CI is not remote owner proof and is not live product proof.
- **Negative space:** preserved old fault scenarios and added new ones; did not replace the suite with only this incident's examples.
- **Self-reference:** independent attestation still requires an external verifier; owner receipts remain self-attested until independently checked.
- **Exact proof binding:** methodology receipt 1.3 now binds exact action; old 1.2/pre-version receipts do not upgrade automatically.
- **Escape paths:** side-channel prohibition, partial discovery autoresume, terminal lease takeover, malformed boolean coercion and derived-cache drift were explicitly attacked.
- **Supersession:** stale lower `COMMITTED` coupling was removed; historical evidence was retained with downgraded assurance instead of remaining simultaneously active as current proof.
- **Generalization:** failures were distilled into cross-owner synthetic faults and learning classes, not owner-specific prose.

## Accepted learning

Future systemic audits should explicitly test these reusable patterns:

1. **untrusted-verifier-input gap** — verifier control inputs need their own trust/completeness boundary;
2. **plan-execution disconnect** — scheduled/declared checks must emit evidence that they actually executed;
3. **schema-coercion privilege escalation** — malformed permission/eligibility metadata fails closed;
4. **complete-discovery / incomplete-presentation split** — truncation cannot alter authoritative eligibility/autoresume semantics;
5. **historical-proof version laundering** — historical evidence keeps provenance but must satisfy the current proof contract before current assurance reuse;
6. **suite/history amnesia** — verifier evolution preserves prior defended counterexamples unless explicitly superseded with evidence.

These are now backed by executable regressions/fault cases where mechanically testable. This audit artifact is cold-path learning evidence; it does not expand normal startup context.
